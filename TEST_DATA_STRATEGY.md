# Test Data Strategy

В мае хочу упростить работу с тестовыми данными в API-тестах.

Основная идея:
- каждый тест должен получать свои данные;
- тесты не должны зависеть друг от друга;
- данные для запросов лучше собирать в одном месте.

Для этого план такой:
- вынести генерацию payload в helper;
- использовать отдельные фикстуры для `POST`, `PUT` и `PATCH`;
- для изменяемых данных использовать `function` scope.

Это особенно полезно в текущем проекте, потому что JSONPlaceholder — fake API. Здесь нет смысла завязывать тесты на реальное сохранение данных после `POST`, `PUT`, `PATCH` или `DELETE`.

Поэтому в тестах основной упор остаётся на:
- статус-код;
- структуру ответа;
- нужные поля;
- соответствие ответа отправленному payload там, где это ожидаемо.
